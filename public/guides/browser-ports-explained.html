Browser ports explained: decompilation, emulation and clean-room builds

Why some browser projects need no extra files and others ask you to supply game data. The four kinds of browser port, how they differ, and why links break so often.

"Playable in your browser" covers at least four different things, and they behave differently when you open them. Knowing which one you are looking at explains most of the confusion around this whole category, including why some links ask for your own game files and others start instantly.

The four kinds of browser port

Native port or rewrite

The game's code is rewritten for the web in JavaScript or WebGL. It starts instantly, needs nothing from you, and often loses some original behaviour along the way.

Decompilation build

Fans reverse-engineer the original game into readable source, then rebuild it for the browser. Very faithful, but it often expects assets from a copy you own.

Clean-room reimplementation

The engine is rebuilt from scratch with free replacement assets. Nothing commercial is used, so it runs without you supplying anything, at the cost of different art and audio.

Emulation

A full emulator runs the original machine's code in the browser. Highest fidelity, heaviest to load, and usually the category most sensitive to copyright complaints.

Why some entries ask for your own game files

Decompilation builds and emulators usually ship the engine but not the content. The engine is the community's work; the levels, textures and audio are still the publisher's. That is why a project can be perfectly legitimate and still ask you to import a game.tar.gz built from your own copy.

Where the line is

Converting files from a game you own is the normal, expected workflow for these projects. Downloading somebody else's game files is not, and it is the single fastest way to get a project taken down. Several entries in this directory have already disappeared or changed address for exactly that reason.

Why links break so often

These are hobby projects running on free hosting, personal domains and community infrastructure. A project can vanish because its domain lapsed, its free tier ran out, or it received a legal notice. The GTA 5 entry in our directory is a good example: the only surviving copy is a web archive, and an archived page is not the same as a working game.

This is also why we show a status note on every page and withhold the launch button on entries whose destination no longer matches the name.
